// One thing per mission

The Copilot Studio concept to land

If a mission runs long, cut steps, not this. Each row is the one idea learners must leave with, and the stumble that most often gets in its way.

MissionLand thisWatch for
01Agent Builder answers; Copilot Studio acts. Tools, agent flows, topics, triggers, channels, and governance are the signals that you've outgrown the easy button.Learners treating it as either/or. It's an upgrade path: start small, move up when the agent has to change something.
02Generative orchestration picks topics, tools, and knowledge by their descriptions. Instructions are capped at 8,000 characters, and Web search should be off for a grounded agent.Vague names and descriptions. Most “the agent ignored my tool” problems are description problems.
03An agent flow is a tool with a typed input/output contract. Severity, IDs, and routing are computed in the flow, never guessed by the model.Typing true as text instead of an expression, and using display names in expressions when the flow only knows the internal input names (text_2, boolean).
04Topics give rule-driven paths: Question nodes with entities validate before anything acts, and Condition nodes branch into known, unknown, incomplete, and sensitive.Acting on an incomplete report, and creating a record before checking what already exists.
05Test the whole flight in a fresh conversation. The activity map shows which tool the orchestrator chose and which inputs it filled.Declaring victory because the pieces worked separately.
06A connection carries an identity. End-user credentials respect each person's access; maker credentials make everyone inherit the maker's. Get items before Create item.Reporting an ID the agent made up instead of the one SharePoint returned.
07Start and wait for an approval pauses the flow until a human decides. Approved, Rejected, and Timed out are three designed paths, and the Escalate topic hands off to a person.The agent saying “done” while the approval is still pending.
08Content is data, never command. Curated knowledge, least-privilege tools, approval gates, and data policies stop what the built-in jailbreak and cross-prompt protections miss.Assuming the model's protections are enough on their own.
09Activity and the flow run history tell you which step broke and why. Evaluation test sets make the scenarios re-runnable, and a failed flow must still respond with an Outcome.Reading only the fails. A “pass” can contain a false claim.
10Publish pushes changes to channels; the test pane runs the draft. The publish dialog flags author-credential tools, and solutions move the agent between environments.Demoing from the draft and forgetting to publish before the real audience tries it.
// Crew roles

Team roles for collaborative mode

Rotate roles at each break so everyone drives at least once.

📐
Role 01

Solution Designer

Owns the what and the why. Reads the mission brief, defines inputs and outputs, decides the branches, and keeps the team on scope.

🛠
Role 02

Builder

Owns the keyboard. Configures the agent, topics, agent flows, and connections in Copilot Studio, and narrates each click aloud.

🛡
Role 03

Risk Reviewer

Owns the “what could go wrong?” question. Challenges permissions, writes the edge-case tests, keeps score, and has the final call in games.

// Abort procedures

Contingency plans

A learner has no Copilot Studio license or access

Pair them with a builder as the team's Risk Reviewer, or move them to the Observer track; the screenshot walkthroughs cover every step.

SharePoint list creation is blocked

Share the pre-built instructor register with Edit permissions (one list per team is fine); last resort, demo Mission 06 from the reference agent while learners do the connection audit.

A connector is blocked by a data policy

Show the error, name it (a data policy, Mission 08), and continue on the reference environment.

Approvals don't arrive

Check the Approvals app in Teams and the approver's Outlook inbox, allow a minute, then run the approval from the reference agent and act on it from the instructor's approver account.

A lab runs long

Cut the stretch steps, never the telemetry check: it's how learners know they succeeded.

The agent responds unexpectedly in the test pane

Start a new test session, open Activity to see which topic or tool was chosen, then fix the description. Most surprises are description problems.

A flow run fails for a learner

Open the flow → Activity → the run: the red step and its HTTP status name the cause. 403 is permissions, 404 is the wrong list or site, 400 is a bad input.

The published agent doesn't show a fix

The channel runs the last published version. Save, Publish, and retry in a new Teams chat.

Reset between cohorts Delete test records created in the register (anything other than DSI-1041 to 1047), remove the Rogue Document from any shared agent, swap the reference agent's working SharePoint connection back in, and clear any pending approvals.
